# news-info-backend Docker 部署说明

本目录已包含整套 Docker 部署文件。`docker-compose` 会一次性拉起 **FastAPI 后端 + MySQL 8 + Redis 7** 三个容器，
服务器上**无需另外安装** MySQL / Redis。

## 一、部署文件清单

| 文件 | 作用 |
| --- | --- |
| `Dockerfile` | 后端镜像构建（Python 3.12-slim，阿里云镜像加速，非 root 运行） |
| `.dockerignore` | 构建时排除虚拟环境、缓存、`.env` 等 |
| `docker-compose.yml` | 基础编排：app + mysql + redis，含数据卷与健康检查 |
| `docker-compose.prod.yml` | 生产覆盖：app 只绑 127.0.0.1、db/redis 不对外、日志轮转 |
| `.env.docker.example` | 容器版环境变量模板（注意 `DB_HOST=mysql`） |
| `scripts/init_db.py` | 首次部署建表 + 播种管理员（可重复执行） |
| `scripts/deploy.sh` | 一键部署脚本（构建→建表→迁移→健康检查） |

## 二、前置条件

服务器安装 Docker 与 Docker Compose 插件：

```bash
# 以 Ubuntu/Debian 为例
curl -fsSL https://get.docker.com | bash
sudo systemctl enable --now docker
docker compose version   # 确认可用
```

## 三、部署步骤

```bash
# 1. 进入后端目录
cd news-info-backend

# 2. 准备环境变量（一定要改默认密码！）
cp .env.docker.example .env
vim .env          # 改 DB_PASSWORD、REDIS_PASSWORD，填 SMTP / 阿里云短信密钥

# 3. 一键部署（推荐）
bash scripts/deploy.sh
```

`deploy.sh` 会自动：构建并启动容器 → 等 MySQL 健康 → 跑 `init_db.py` 建表+播种管理员 →
跑 `run_migration.py` 补列 → 轮询健康检查 → 打印容器状态。

> 默认种子管理员：账号 `admin` / 密码 `admin123`，登录后请尽快改密码。

### 手动部署（等价于脚本）

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec app python scripts/init_db.py
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec app python scripts/run_migration.py
```

> 本机快速验证可省略 prod 覆盖文件：`docker compose up -d --build`，后端直接暴露在 `http://localhost:8000`。

## 四、验证

```bash
docker compose ps                       # 三个容器都应是 healthy
curl http://localhost:8000/             # 返回 {"message":"Hello FastAPI"}
# 浏览器打开 http://<服务器IP>:8000/docs 查看接口文档
```

## 五、常用运维命令

```bash
docker compose logs -f app              # 看后端实时日志
docker compose ps                       # 容器状态
docker compose restart app              # 重启后端
docker compose down                     # 停止并删除容器（数据卷保留）
docker compose exec app sh              # 进后端容器
docker compose exec mysql mysql -uroot -p   # 进 MySQL

# 备份数据库（数据存在名为 mysql-data 的 docker volume 里）
docker compose exec mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" news_app' > backup.sql
```

## 六、几个关键点（容易踩坑）

1. **`.env` 里 `DB_HOST=mysql`、`REDIS_HOST=redis`**，用的是 compose 服务名而不是 `localhost`——
   容器之间通过内部网络用服务名互相访问。本地开发用的 `.env`（`localhost`）不要直接拿来部署。
2. **`DB_PASSWORD` 同时是 MySQL 容器的 root 密码**，`REDIS_PASSWORD` 同时是 Redis 的 `requirepass`，
   首次启动时由这两个值初始化，务必在第一次 `up` 之前设置好。
3. **首次部署必须跑 `init_db.py`**：应用启动时不会自动建表。
4. **上传的图片** 落在 `static/uploads/`，已挂载到宿主机目录持久化；MySQL/Redis 数据存在 docker volume，
   `docker compose down` 不会丢，`down -v` 才会删卷。
5. 端口：基础配置把 MySQL 映射到宿主机 `3307`、Redis 映射到 `6380`，避免和服务器上已装的同类服务冲突；
   生产覆盖文件则完全不对外暴露这两个端口。

## 七、前端怎么部署（不在本次 Docker 范围内）

两个前端（`news-info-frontend` 移动端、`news-info-admin` 管理端）都是 Vite 项目，构建成静态文件后用 nginx 托管即可：

```bash
cd news-info-frontend && npm install && npm run build   # 产物在 dist/
cd ../news-info-admin   && npm install && npm run build   # 产物在 dist/
```

> 注意：移动端 `news-info-frontend/src/config/api.js` 里把后端地址**写死成** `http://127.0.0.1:8000`，
> 上线前需改成你的服务器域名/IP（或改造成相对路径走 nginx 反代）。

nginx 参考配置（前端静态 + 反代后端 `/api`、`/static`）：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 移动端
    location / {
        root /var/www/news-info-frontend/dist;
        try_files $uri $uri/ /index.html;
    }

    # 管理端（放到 /admin 子路径，按需调整）
    location /admin {
        alias /var/www/news-info-admin/dist;
        try_files $uri $uri/ /admin/index.html;
    }

    # 反代后端接口与上传文件到容器（app 只绑了 127.0.0.1:8000）
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    location /static/ {
        proxy_pass http://127.0.0.1:8000;
    }
}
```
